# AI-EDDA

AI-EDDA — локальный редактор карт для **Ragnarock** с анализом музыки и ручным редактированием четырёх дорожек.
Python-сервер хранит проекты и выполняет обработку. React-интерфейс открывается в браузере.

## Возможности

- Загрузка OGG/Vorbis, MP3, WAV и FLAC с устройства, где открыт браузер.
- Анализ долей, начал тактов и ритмических признаков с Beat This и DSP.
- Редактирование темпа, сетки, музыкальных точек и временных привязок нот.
- Добавление, перемещение, разделение, объединение и копирование нот; защита ручных изменений; Undo/Redo.
- Генерация заготовки на одной дорожке с просмотром перед применением.
- Метаданные, обложка, прослушивание фрагмента и диагностика карты.
- Экспорт одной–трёх карт в игровой ZIP; native backup с историей и результатами анализа.

V0 требует проверки карты человеком. Генерация не заменяет полноценную ручную аранжировку.
Импорт игровых пакетов поддерживает определённый профиль формата; не любой архив Ragnarock Customs совместим с ним.

## Быстро посмотреть интерфейс без backend

Нужны только **Node.js 24** и npm. Из корня checkout:

```powershell
cd web
npm ci
npm run dev:demo
```

Откройте адрес, который напечатает Vite. Demo использует те же компоненты редактора и заполненные синтетические проекты.
Python, GPU, модель и сервер не нужны. Это отдельные локальные демонстрационные данные; анализ и задания имитируются.
Обычные пользовательские проекты этот режим не изменяет. Сброс demo восстанавливает начальные примеры.

[Руководство по frontend](web/README.md) описывает режимы запуска, тесты и структуру интерфейса.

## Установить настоящее приложение

Поддерживаемая среда V0 — Windows. Setup устанавливает локальные uv и Python 3.12.11, затем зависимости из lock-файла.
Для сборки интерфейса из GitHub checkout нужен Node.js 24. В готовой поставке интерфейс уже собран; Node.js для запуска не нужен.

Из корня проекта выполните:

```powershell
# Для NVIDIA CUDA
.\setup.ps1 -Device cuda -DownloadModel

# Либо для CPU
.\setup.ps1 -Device cpu -DownloadModel
```

Выберите одну команду. Setup запросит пароль владельца при первом запуске и сохранит существующий пароль при повторной установке.
`-DownloadModel` загружает checkpoint и проверяет размер и SHA-256. Для ручного редактирования модель не обязательна.
Зависимости устанавливаются локально; системная Anaconda не используется.

Запуск:

```powershell
.\start.ps1
```

По умолчанию адрес — **http://127.0.0.1:8000**. Войдите с паролем, заданным при установке.
Остановка — Ctrl+C в терминале сервера. Если порт занят, используйте `./start.ps1 -Port 8765`.
Тестовый стенд использует RTX 4090. Развёртывание на RTX 3060 6 ГБ и игровой запуск в PCVR требуют отдельной проверки.

### Доступ с другого компьютера

Для сетевого доступа нужны HTTPS, сертификат с именем/IP сервера, доверие к CA на клиенте и разрешённый порт.
Сервер не разрешает обычный HTTP вне localhost. Пошаговая настройка: [установка Windows](docs/INSTALL_WINDOWS.md).
Музыка загружается из браузера; анализ и хранение выполняются на сервере. Прослушивание и скачивание доступны на клиентском устройстве.

## Где находятся данные

| Данные | Стандартная папка Windows |
|---|---|
| Проекты | Системная папка Documents\AI-EDDA\<project-id> |
| Настройки владельца, задания и экспорт | %LOCALAPPDATA%\AI-EDDA |
| Модель | %LOCALAPPDATA%\AI-EDDA\models\beat-this\final0.ckpt |
| Python-окружение и uv | .venv и .tools внутри установки |

Setup и start принимают `-ProjectRoot` и `-ConfigRoot` для явного выбора папок. При запуске используйте те же значения, что при установке.
Пользовательские данные, модель, пароли, сертификаты и рабочие окружения не включаются в Git.
Храните native backup отдельно от рабочего каталога проекта.

## Основной сценарий

1. Создайте проект и загрузите музыку. Примените подготовленное аудио.
2. Выполните анализ или отредактируйте сетку вручную.
3. Проверьте темп и временные привязки. Создайте карты и расставьте ноты.
4. При необходимости получите single-lane черновик, просмотрите его и примените явно.
5. Заполните метаданные, обложку и параметры выбранных карт.
6. Скачайте игровой ZIP для Ragnarock и native backup для дальнейшего редактирования.

Vorbis сохраняется побайтно. Другие входные форматы преобразуются в конечный OGG; анализ и preview используют его декодированный PCM.
Native backup ограничен 1 GiB в ZIP, 2 GiB после распаковки и 10 000 файлов. При превышении лимита приложение сообщает ошибку.
Игровой ZIP не содержит полной истории проекта. Публикация на сторонних площадках выполняется пользователем отдельно.

## Разработка

Backend находится в `src/ai_edda`, frontend — в `web`. Менять layout, стили и компоненты можно через demo без установки Python.
Для проверки настоящего API запустите backend, затем в другом терминале:

```powershell
cd web
npm ci
$env:AI_EDDA_API_TARGET = 'http://127.0.0.1:8000'
npm run dev
```

Vite проксирует `/api` на заданный сервер. По умолчанию используется адрес выше.
В production frontend раздаёт FastAPI; отдельный процесс Node.js не нужен.
Схема и TypeScript DTO хранятся в репозитории. Их регенерация требует Python, обычная разработка UI — нет.

### Проверки frontend

Из `web`:

```powershell
npm run typecheck
npm test
npm run test:ui
npm run test:demo
npm run build
```

`test:ui` не вызывает Python. `test:frontend` запускает также проверки совместной работы frontend/backend и требует Python-окружение.
`test:demo` проверяет демонстрационные данные и открывает интерфейс в headless-браузере; требования описаны в [web/README.md](web/README.md).

### Проверки приложения

После setup установите developer dependencies с тем же профилем:

```powershell
.\.tools\uv.exe sync --frozen --extra cpu
.\scripts\check.ps1
```

Для CUDA замените `cpu` на `cuda`. Не смешивайте эти extras.
Общий checker проверяет Python, схему и DTO, TypeScript, frontend и production build.
Проверки настоящей модели, GPU и PCVR описаны отдельно: [MODEL_CHECKS.md](docs/MODEL_CHECKS.md).
[Команды regression checks](scripts/frontend-checks.md) содержат подробности режимов и пропусков.

### Собрать поставку

```powershell
npm --prefix web run build
.\.venv\Scripts\python.exe scripts/build_release.py --output dist
```

Результат — исходный ZIP с готовым frontend, manifest с hashes файлов и Python wheel.
Модель, музыка, локальные проекты и окружения в поставку не входят.

| `web/tests` | Frontend regression checks |

| `fixtures` | Синтетические контрольные данные |
| `scripts` | Проверки, схемы и сборка поставки |
| `docs` | Инструкции по установке, зависимостям и модели |
