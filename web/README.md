# Разработка интерфейса AI-EDDA

Frontend использует React, TypeScript и Vite. Один набор компонентов работает с настоящим API и демонстрационными данными.
Для изменения интерфейса достаточно Node.js 24 и npm. Python, GPU и модель в demo не нужны.

## Запуск без backend

Из каталога `web`:

```powershell
npm ci
npm run dev:demo
```

Откройте `http://127.0.0.1:5174`. Если порт занят, Vite завершится с ошибкой.
Demo содержит два синтетических проекта с несколькими картами, нотами, обложкой и коротким звуковым сигналом.
MSW перехватывает запросы API внутри браузера. Этот режим не подключается к серверу приложения.

Изменения сохраняются в localStorage текущего браузера. Работайте с demo в одной вкладке.
Кнопка сброса восстанавливает исходные проекты. Она не затрагивает настоящие проекты AI-EDDA.
Панель demo также позволяет воспроизвести медленные ответы и ошибки.

Поддерживается изменение данных песни и карты, добавление, перемещение и удаление нот, выбор результата анализа.
Анализ и генерация имитируют задания для проверки панелей. Черновик можно открыть и прослушать.
Генерация поддерживает дорожку 0, subdivision 1, seed 0 и весь диапазон 0–30 секунд.
Задания и новые черновики существуют до перезагрузки страницы. Изменения карт и отклонение черновиков сохраняются локально.
Импорт, экспорт, применение черновика и остальные команды возвращают явное сообщение об ограничении.
Demo не проверяет качество модели, совместимость игрового ZIP или правильность всех серверных команд.

## Работа с настоящим API

Запустите приложение по [основной инструкции](../README.md). Затем выполните из `web`:

```powershell
$env:AI_EDDA_API_TARGET = 'http://127.0.0.1:8000'
npm run dev
```

Откройте адрес Vite и войдите с паролем установленного приложения.
`AI_EDDA_API_TARGET` задаёт адрес backend; по умолчанию используется `http://127.0.0.1:8000`.
Vite проксирует `/api`, включая cookies. В этом режиме изменения сохраняет настоящий backend.

## Где менять интерфейс

| Файлы | Назначение |
|---|---|
| `src/App.tsx`, `src/style.css` | Рабочая область, навигация и основные формы |
| `src/TimelineEditor.tsx`, `src/timeline.css` | Ноты, выделение и взаимодействие с timeline |
| `src/*Panel.tsx` | Панели анализа, сетки, генерации, экспорта и свойств |
| `src/AudioTransport.tsx`, `src/transport.ts` | Прослушивание и позиция воспроизведения |
| `src/WaveformView.tsx`, `src/waveform.css` | Waveform |
| `src/useProject.ts`, `src/api.ts`, `src/*Client.ts` | Состояние проекта и запросы к серверу |
| `src/generated/ui-contract.ts`, `schema/ui-contract.json` | Сохранённые DTO и JSON Schema |
| `src/demo` | Синтетические данные, хранение и обработчики MSW |
| `demo-public` | Worker MSW и собственная демонстрационная обложка |
| `tests`, `tests/regression`, `tests/demo` | Проверки компонентов, сценариев и demo |

Меняйте общие компоненты, чтобы результат был виден в обоих режимах.
Если меняется контракт API, обновите Python-модели и сгенерированные файлы вместе.
Для регенерации нужен настроенный backend в `../.venv`:

```powershell
npm run generate
```

## Проверки и сборка

Из `web`:

```powershell
npm run typecheck
npm test
npm run test:ui
npm run test:demo
npm run build
```

`test:ui` выполняет проверки без Python. `test:frontend` дополнительно запускает совместные проверки с Python.
`test:demo` запускает тесты обработчиков и настоящий браузер в headless-режиме.
Для браузерной проверки нужен установленный Microsoft Edge или Google Chrome; также подходит Chromium из Playwright.
Если подходящего браузера нет, выполните `npx playwright install chromium`. Экран пользователя не используется.
Результаты браузерной проверки сохраняются в исключённом из Git каталоге `src/scratch/github-preparation/demo-check`.

Обычная сборка записывается в `../src/ai_edda/static`; этот каталог раздаёт Python-сервер.
Она не содержит демонстрационные проекты, worker или обработчики MSW.
Чтобы не заменять файлы запущенного приложения, используйте отдельный каталог:

```powershell
npm run build -- --outDir ../build/frontend
```
